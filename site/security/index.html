How we check skills

A skill is instructions and sometimes code that your agent follows, so it can do anything your agent can. We check skills, show what we found for the exact version you'd install, and say plainly what we haven't checked. A check is not a guarantee: read a skill before you install it.

What the badges mean

Library skills show our review beside their stars. In the app it’s a shield you can hover or tap for the details.

  • No issues found. Our rule checks and an AI review checked this exact version and found nothing hidden or out of place for what the skill says it does, or a second look cleared what they flagged. Steps that are out in the open and expected, like running a tool’s official installer, can still pass.
  • Under review. Our checks flagged something in this version and the second look didn’t clear it. Read it closely before you install it.
  • Not reviewed yet. We haven't checked this version: it's outside the skills we review today, too big, has files we can't read, or changed since we last checked.

A badge belongs to one version. Installs from omgskills use that same pinned version, and when a skill changes, its new version shows “Not reviewed yet” until we check it.

Public skills: three layers

  • Rule checks look for keys and passwords, download-and-run commands, instructions hidden from the reader, invisible characters, private data being sent out, and hidden or compiled code.
  • AI review. Claude reads every text file and answers a fixed checklist: does the skill send data out, read secrets, run downloaded or hidden code, change your system or agent settings, hide what it does, try to steer the agent or a reviewer, load instructions from the web, or delete data or act on your accounts? Each answer is compared with what the skill says it's for.
  • Second look. When the rules or the review flag a skill, a larger Claude model reads the same files. If it agrees, or declines to answer, the skill stays “Under review”.

We never run skill files; we only read them as text. Rule checks run in a sandbox with no internet access. For the AI review, the text of public skills is sent to Anthropic’s API.

Which skills we review

Today: the skills in our collections and creator picks, about 3,700. The rest of the library (about 46,000 skills) isn’t reviewed yet and says so. A skill too big to review in full, or with files we can’t read such as PDFs, archives or programs, also stays “Not reviewed yet” rather than getting a partial pass.

How well it works

We tested on MaliciousSkillBench, a public set of known-harmful and harmless skills, using a held-out part from sources we never tuned on, measured once:

  • The AI review plus second look flagged 63% of harmful skills and 1.5% of harmless ones. Most harmful skills it missed relied on a file that wasn't included in the test samples.
  • Rule-based scanners alone, ours and open-source ones we tested, caught 3–8% of harmful skills from unfamiliar sources, which is why we add the AI review.
  • On a sample of 99 public creator picks, 98% came out “No issues found” after the second look.

So a badge lowers the risk; it doesn't remove it. Harmful skills can still get through.

Private skills

Skills you keep in My skills are never sent to an AI. They get our rule checks on our own scanner, plus a sharing check that points out email addresses, paths into someone’s home folder, and addresses only reachable inside your network. A private skill with none of these, and none of the rule-check findings above, shows Team-safe. That covers what we check for, nothing more; the results are visible only to you and the people you share the skill with.

Report a problem

If a skill looks harmful, or a badge looks wrong, email hi@omgskills.com with the skill's link. For a security issue in omgskills itself, open a GitHub security advisory. Please don't include live keys or personal data.
